# Устройство компилятора

```
исходник .ot
   │  lexer.rs     токены (+ комментарии для fmt)
   ▼
   │  parser.rs    AST (ast.rs), рекурсивный спуск + Pratt для выражений
   ▼
   │  driver.rs    загрузка импортов, объединение модулей
   ▼
   │  check.rs     разрешение имён, проверка типов, понижение синтаксиса
   ▼
 Module (типизированный AST)
   ├── codegen/llvm.rs → LLVM IR → clang + runtime/orbitron_rt.c → исполняемый файл
   └── codegen/jvm.rs  → Main.java → javac + runtime/OtRt.java → .jar
```

| Файл | Назначение |
|---|---|
| `src/main.rs` | командная строка |
| `src/driver.rs` | загрузка файлов, поиск stdlib, запуск clang/javac |
| `src/diag.rs` | позиции в исходнике и вывод ошибок с подсветкой строки |
| `src/lexer.rs` | лексер; интерполяции строк сразу разбиваются на токены |
| `src/parser.rs` | парсер |
| `src/ast.rs` | AST: поверхностные и разрешённые формы выражений |
| `src/types.rs` | семантические типы |
| `src/check.rs` | проверка типов |
| `src/codegen/llvm.rs` | генерация LLVM IR |
| `src/codegen/jvm.rs` | генерация Java |
| `src/fmt.rs` | форматтер |
| `src/project.rs` | `orbitron.toml` и `orbitron new` |
| `runtime/` | рантаймы обоих бэкендов (встраиваются в компилятор через `include_str!`) |

## Проверка типов

`check.rs` работает в несколько проходов:

1. собирает имена структур, перечислений и констант;
2. разрешает типы полей структур;
3. собирает сигнатуры функций, методов (`Тип::метод`) и `extern fn`;
4. вычисляет константы (с обнаружением циклов);
5. проверяет тела функций.

Во время проверки AST переписывается, чтобы бэкендам не приходилось искать имена:

- `Ident` → `Local(id)`, `FnRef`, или литерал константы;
- `Call`/`MethodCall` → `CallFn`, `CallExtern`, `CallIndirect` или `CallBuiltin`;
- `Field` → `FieldIdx` с номером поля;
- литерал структуры → `New` с полями в порядке объявления;
- `a |> f(b)` → `f(a, b)`;
- анонимная функция выносится в отдельную функцию `lambda#N` и заменяется на `FnRef`;
- `Paren` убирается.

Каждому выражению записывается тип. Тип `Never` (у `return`, `break`, `panic` и т. п.) совместим с любым, что позволяет корректно проверять ветки и наличие возврата. Тип `Error` подавляет каскад сообщений после первой ошибки.

## LLVM-бэкенд

Генерирует текстовый IR, поэтому не зависит от библиотек LLVM при сборке компилятора. Локальные переменные и результаты `if`/`match` хранятся в `alloca`, а clang `-O2` переводит их в регистры (mem2reg). Каждое значение массива занимает 8-байтовую ячейку, поэтому массивы любых типов используют один набор функций рантайма. Структуры размещаются в куче и передаются как указатели.

`defer` реализован статически: стек областей с отложенными выражениями. При выходе из блока, `return`, `break` или `continue` код соответствующих областей подставляется в место выхода.

## JVM-бэкенд

Java не является языком выражений, поэтому блочные выражения (`if`, `match`, блоки), используемые как значения, понижаются в инструкции, которые присваивают значение временной переменной. Чтобы сохранить порядок вычисления слева направо, предыдущие операнды сохраняются во временные переменные, когда следующему операнду нужны инструкции. Отслеживается достижимость кода, чтобы не порождать недостижимые инструкции, на которые ругается javac.

Соответствие типов: `int` → `long`, `float` → `double`, `bool` → `boolean`, `str` → `String`, `[T]` → `ArrayList<T>`, структуры → `static final class S_Имя`, перечисления → `long`, функциональные типы → сгенерированные интерфейсы `F0`, `F1`, ...

## Как добавить встроенную функцию

1. Добавить вариант в `Builtin` и имя в `Builtin::function` (`ast.rs`).
2. Описать типы в `Checker::builtin` (`check.rs`).
3. Реализовать в `codegen/llvm.rs` (при необходимости функцией в `orbitron_rt.c`) и в `codegen/jvm.rs` (при необходимости в `OtRt.java`).
4. Добавить тест в `tests/programs` с эталонным `.out` и описание в `docs/language.md`.
