# Участие в разработке

## Окружение

- Rust 1.75+ (`rustup`)
- `clang` — для LLVM-бэкенда и тестов
- JDK 17+ — для JVM-бэкенда (без него JVM-тесты пропускаются)

```bash
cargo build
cargo test                      # всё
ORBITRON_SKIP_JVM=1 cargo test  # без JVM
cargo clippy
```

Устройство компилятора описано в [docs/internals.md](docs/internals.md).

## Тесты

- `tests/programs/*.ot` — программы с эталонным выводом `*.out`. Каждая собирается обоими бэкендами, вывод должен совпасть с эталоном. Заголовок `// exit: N` задаёт ожидаемый код завершения, `// stderr: текст` — строку, которая должна быть в stderr.
- `tests/errors/*.ot` — программы, которые не должны компилироваться. Каждая строка `// ошибка: текст` должна встретиться в выводе компилятора.
- `examples/` и `stdlib/` должны проходить `orbitron check` и `orbitron fmt --check`.

Чтобы добавить тест, напишите программу, получите вывод через `orbitron run file.ot > file.out`, **проверьте его вручную** и убедитесь, что `--backend jvm` даёт то же самое.

## Правила

- любое изменение семантики реализуется в **обоих** бэкендах и обоих рантаймах (`runtime/orbitron_rt.c` и `runtime/OtRt.java`) и покрывается тестом из `tests/programs`;
- ошибки в пользовательской программе не должны приводить к панике компилятора. Сообщайте о них через `Diag` с позицией и, по возможности, примечанием с советом;
- сообщения компилятора и документация пишутся на русском языке, комментарии в коде на английском;
- код на Orbitron форматируется через `orbitron fmt`, код на Rust через `cargo fmt`;
- новая возможность языка описывается в `docs/language.md`.

## Pull request

1. Создайте ветку от `main`.
2. Убедитесь, что `cargo test` и `cargo clippy` проходят.
3. Опишите в PR, что изменилось и зачем.
